# Production owner actions

Engineering can prepare and validate these integrations, but it cannot manufacture the
legal identity, accounts, human evidence, or private credentials they require.

## Required before a Windows public stable release

1. Approve a software license and third-party redistribution policy.
2. Confirm the final product/company name after trademark review.
3. Reserve the Windows Store/package identity if MSIX distribution will be supported.
4. Obtain an organization-validated code-signing identity or managed signing service.
5. Provide public HTTPS privacy, security, support, and release-note URLs.
6. Enable private vulnerability reporting and define a monitored security contact.
7. Commission an independent application security review and remediate findings.
8. Complete consented keyboard, Narrator/NVDA, migration, and data-recovery sessions.
9. Run a real two-device OneDrive offline/edit/reconnect/conflict matrix.

## Required before a macOS stable release

- Apple Developer Program membership.
- Developer ID Application and installer identities.
- Protected signing configuration, hardened runtime, entitlements, notarization, and
  staple verification.
- Apple Silicon and supported Intel/macOS qualification where applicable.

## Required before a Linux stable release

- Resolve the Tauri GTK3 `glib` unsoundness dependency or obtain a time-bounded independent
  risk acceptance supported by reachability analysis.
- Run installed GUI workflows on supported distributions under Wayland and X11.
- Decide whether `.deb`, AppImage, Flatpak, or a combination is the supported channel.

## Required before recommended local AI

- Select a redistributable model and approve its license.
- Freeze an immutable manifest containing URL, exact bytes, SHA-256, and memory floor.
- Run the documented Windows/macOS/Linux hardware matrix and publish measured results.

## Required before paid AI

- Create provider test accounts with strict spend caps.
- Approve each provider’s privacy/data-retention terms and endpoint profile.
- Validate authentication, token accounting, pricing display, 429 handling, malformed
  responses, outages, and user-set cost limits.

No passwords, signing keys, API keys, store credentials, or notarization secrets should be
placed in this repository or supplied in chat.
